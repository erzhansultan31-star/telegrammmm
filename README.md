# Telegram Music Profile Bot / Музыка авто-профиль боты

**Логика өте қарапайым:**
1. Мұқаба мен автор атын **бір рет** орнатасың (мәзірден).
2. Содан кейін **кез келген уақытта** mp3 жіберсең,
3. Бот оны **автоматты түрде** сол мұқаба+автормен өңдеп, дайын
   файлды **бірден қайтарады**. Ешбір қосымша батырма басудың
   қажеті жоқ.

Қосымша: 🔍 iTunes арқылы музыка іздеп, табылған автор мен
мұқабаны бір батырмамен профиліңе сақтауға болады.

## Авторлық құқық туралы ескерту

Музыка іздеу — Apple-дың ашық **iTunes Search API** арқылы жұмыс
істейді (тек ат/автор/мұқаба қайтарады, толық ән файлын жүктемейді).
Бот пайдаланушының **өз mp3 файлына** ғана тег/мұқаба қосады.

## Неге "Conflict" және "Timed Out" қателері шықты (түзетілді)

Ескі нұсқада бот тек `polling` режимінде жұмыс істеді, яғни ешбір
HTTP порт ашылмады. Ал Render "Web Service" ретінде деплой еткенде
міндетті түрде `$PORT` портының ашылғанын тексереді — ашылмаса,
"Timed Out" деп есептеп сервисті өлтіріп, қайта-қайта рестарт
жасайды. Әр рестартта ескі процесс толық өшпей тұрып, жаңасы іске
қосылғандықтан, екі instance бір токенмен қатар `getUpdates`
сұрауын жіберіп, Telegram "Conflict: terminated by other getUpdates
request" қатесін қайтарған.

**Түзетуі:** `main.py` енді `polling`-пен **қатар** жеңіл HTTP
health-check сервер де ашады (`aiohttp`, `/` маршруты). Render порт
ашылғанын көріп, сервисті "тірі" деп таниды, өшірмейді — ақылы
Background Worker де, webhook та керек болмайды.

**Егер тағы да "Conflict" қатесі шықса:**
- Ботты өз компьютеріңізде (`python main.py`) және Render-де **бір
  мезгілде екеуін бірдей** іске қоспаңыз — тек біреуі ғана жұмыс
  істеуі керек.
- Render Dashboard → сервис → "Manual Deploy" → ескі деплойдың
  толық тоқтағанын күтіңіз (логта "Polling stopped" жолы шығады),
  содан кейін жаңасын іске қосыңыз.
- Бірнеше Render сервисі бір `BOT_TOKEN`-мен деплой етілмегеніне
  көз жеткізіңіз.

## Неге мұқаба "сақталды" деп жазса да көрінбей тұрды (түзетілді)

Тег жазу коды дұрыс жұмыс істеп тұрды — мұқаба mp3 файлдың ішіне
(ID3 APIC фреймі ретінде) шынымен ендірілген болатын. Бірақ дайын
файл `answer_document` (жай құжат) түрінде жіберілгендіктен, Telegram
чатта ID3 ішіндегі мұқабаны автоматты түрде көрсетпейді — тек арнайы
"audio" хабарлама түрінде, бөлек `thumbnail` параметрімен жіберілгенде
ғана бірден көрінеді.

**Түзетуі:** енді бот дайын файлды `answer_audio` арқылы, мұқабадан
жасалған кіші thumbnail-мен бірге жібереді — Telegram-да мұқаба,
атауы және авторы бірден көрінеді, әрі файлдың өзінде де толық
өлшемді мұқаба ендірілген күйде қалады (кез келген музыка плеерде
көрінеді).

## Тұрақты сақтау (Neon/Supabase Postgres) — профиль рестартта жоғалмас үшін

Әдепкі жағдайда (DATABASE_URL қойылмаса) бот деректерді тек жадыда
сақтайды — сервер рестарт жасаса (redeploy, sleep/wake), барлық
пайдаланушылардың мұқабасы мен авторы жоғалады. Мұны түзету үшін
тегін сыртқы Postgres қосыңыз:

### Neon.tech арқылы (ұсынылады, тегін)
1. [neon.tech](https://neon.tech) сайтында тіркеліп, жаңа жоба құрыңыз.
2. Dashboard-та **Connection string**-ті көшіріп алыңыз, мысалы:
   `postgresql://user:password@ep-xxx-xxx.us-east-2.aws.neon.tech/neondb?sslmode=require`
3. Render-де сервисіңіздің Environment Variables бөліміне
   `DATABASE_URL` деп осы сілтемені қойыңыз.
4. Қайта деплой етіңіз. Логтан `Storage: Postgres (тұрақты...)` деген
   жолды көресіз — бот кестені (`fsm_storage`) өзі автоматты жасайды.

### Supabase.com арқылы
1. [supabase.com](https://supabase.com) → жаңа жоба → Settings →
   Database → **Connection string** (URI, "Transaction" режимі емес,
   "Session" немесе тікелей қосылым режимін таңдаңыз).
2. Жоғарыдағыдай `DATABASE_URL` ретінде Render-ге қойыңыз.

Осыдан кейін мұқаба мен автор деректері базада сақталады, сервер
қанша рет рестарт жасаса да жоғалмайды.

## Құрылым

```
telegram_bot/
├── main.py           # бот логикасы + polling + health-check сервер
├── locales.py         # RU/KZ мәтіндер сөздігі
├── states.py           # FSM күйлері
├── keyboards.py        # ықшам инлайн батырмалар (5 батырма)
├── audio_utils.py       # ID3 тег жазу (mutagen): автор, мұқаба
├── music_search.py      # iTunes Search API арқылы музыка іздеу
├── storage.py            # Postgres-те тұрақты FSM storage
├── requirements.txt
├── render.yaml          # Render.com конфигурациясы
└── .env.example
```

## 1. Локалды тест

```bash
pip install -r requirements.txt
export BOT_TOKEN=сіздің_токен   # Windows: set BOT_TOKEN=...
python main.py
```
Telegram-да ботқа `/start` жазыңыз.

## 2. Render.com-ға тегін deploy ету

1. Осы папканы GitHub-қа жүктеңіз.
2. [render.com](https://render.com) → **New → Blueprint** → репозиторийді
   таңдаңыз (`render.yaml` бар болғандықтан баптауларды өзі оқиды).
3. Environment Variables-қа тек **`BOT_TOKEN`** қойыңыз — басқа
   ештеңе керек емес (WEBHOOK_URL де керек емес).
4. Deploy болғанда логтан мына жолды көресіз:
   `Health-check сервері 10000 портында ашылды` — бұл сервистің
   дұрыс жұмыс істеп тұрғанының белгісі.

## Мәзір (5 батырма)

| Батырма | Не істейді |
|---|---|
| 🖼 Мұқаба | Профильге тұрақты мұқаба суретін сақтайды |
| 👤 Автор | Профильге тұрақты автор атын сақтайды |
| 🔍 Музыка іздеу | iTunes-тен іздеп, табылған автор+мұқабаны профильге сақтауға ұсынады |
| 🌐 Тіл | RU/KZ ауыстыру |
| 🗑 Тазарту | Сақталған мұқаба мен авторды өшіреді |

Осы бестен басқа ешбір батырма жоқ — қалғанының бәрі автоматты:
**кез келген уақытта mp3 жібер, бот бірден дайын файлды қайтарады.**

## Кеңейту идеялары

- Профильді SQLite/файлға сақтау (қазір тек жады — Render рестарт
  жасаса профиль жоғалады, кодта тек процесс жұмыс істеп тұрғанда
  сақталады).
- Әр пайдаланушыға бірнеше профиль (мысалы, әр каналға бөлек).
- Ән атын (title) да өзгерту опциясын қосу.
